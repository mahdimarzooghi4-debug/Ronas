# Ronas — explicit separate local authority journal checkpoint (LOCAL/TEST)

**Status:** versioned technical recovery-integrity experiment only, not Production recovery service, immutable external evidence, human review, or legal/financial/science approval. Uses a *separate* private local SQLite file, **not** an off-host or independent WORM anchor. No fabricated retention, recovery time, legal expiry, provider, external secret, or scientific rule.

The existing append-only `SqliteSyntheticAuthorityRevisionJournal` now pins a randomly generated `journal_instance_id` on initialization, persisted in its `authority_metadata`. Existing local journal files are assigned one on the first open after this development migration. `SqliteLocalAuthorityCheckpoint(path)` uses its own private 0600 local file. It writes explicit immutable chained `local_checkpoint` records holding journal ID, highest event sequence, and exact global SHA-256 event head. It has independent SQLite transactional CAS-style serialization and immutable history triggers. This is a **local checkpoint**, not a cryptographic signature or independently witnessed head.

`pin_current(journal)` is an **explicit test/developer action**, not automatic trust repair. It verifies the journal's internal event/owned-state chain, locks the source journal during pinning, checks the separate checkpoint file's own append-only history, and refuses a different journal instance, a lower event sequence, or a head which does not descend from the previous pinned head. It then appends a new checkpoint only if journal progress is a verified strict extension. An unchanged head is idempotent. The source journal remains locked until the separate checkpoint write has committed.

`assert_current(journal)` requires an existing checkpoint which matches the exact current journal ID/event sequence/head. A newer **unpinned** journal is not silently trusted, and an older valid database restored by SQLite backup after a newer head has been pinned fails closed. A different newly created journal file at the same path and the same empty event count also fails by instance ID mismatch. The checkpoint is not a source of candidate state or a grant of authority.

**Precise limits:** This detects rollback/replacement of the original journal *only while a later separate sidecar checkpoint remains intact and trusted*. If an attacker restores, deletes or forges both files together, creates a new sidecar and explicitly re-pins an old database, or performs a privileged coordinated rewrite, there is NO external anchor to detect it. Sidecar `pin_current` must therefore not be silently re-run to legitimize recovered old data. A true independent, remote, access-controlled immutable attestation/backup provider would require separate governance and real infrastructure. This is not an automatic rollback-proof guarantee, a Production backup protocol, nor a distributed transaction. No real source rights, certified professional expertise, actual plan approval or Stage/Release/Production.


## Recovery inspection without trust reset (LOCAL/TEST)

New `open_existing(path)` recovery-specific constructors on the local authority journal and sidecar checkpoint **do not create a missing file, missing schema, trigger, or new journal-instance ID**. They use SQLite `mode=rw`, never `mode=rwc`; disappearance of the file between the initial existence check and opening does not create a replacement. The existing default constructors remain explicitly for first-time LOCAL/TEST setup, and **must not be used in a recovery procedure**. Strict recovery opening of partial/corrupt SQLite fails closed; missing mandatory triggers are never silently reinstalled.

`inspect_local_recovery(journal_path, checkpoint_path)` is a read-only internal diagnostic: it refuses relative/identical paths, never creates a file or calls `pin_current`, and reports a fixed state. States distinguish absent one/both files, corrupt source, corrupt checkpoint, no pin, replaced journal instance, journal behind checkpoint, journal ahead with an unpinned verified extension, divergent history and exact match. It checks the previously pinned historical ancestor when the source is ahead. The only case with `local_checkpoint_matches=true` is `MATCHED`; `independent_external_attestation=false` ALWAYS. Classification is momentary and does **not** authorize later decisions: an actual use must re-execute `assert_current` under its existing locks.

Tests cover same-point exact match without any new event/pin; loss of either/both files with no auto-recreation; an earlier valid source restored alongside a later checkpoint; an earlier valid checkpoint restored alongside a newer source; replacement with a new journal of the same event count; tampered triggers; incomplete empty SQLite files; and **both files coherently rolled back**, which still appears locally matched and demonstrably **cannot** be detected with local evidence alone. No backup retention/RPO/RTO or external anchor is invented.

**Critical:** A privileged operator who deletes the checkpoint and calls the first-time *creation* constructor to mint a fresh checkpoint can still manually re-pin old data. Enforcing genuine provenance across such a reset requires separately administered independent durable off-host evidence, which this LOCAL/TEST slice does not possess.
