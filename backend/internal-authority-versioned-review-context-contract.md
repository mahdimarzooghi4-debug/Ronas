# Ronas — Provider-owned case-scoped revision witnesses (LOCAL/TEST)

The optional read-only GET /api/v1/agronomy/assigned-drafts/{ref}/review-context-versioned?observed_specialist_revision=N is a stricter, separate synthetic specialist-context route. Unlike the older review-context-impact route, this new route requires THREE explicitly configured independent provider callbacks to supply monotonically increasing scoped generations for SCIENCE_SOURCE_CANDIDATES, SPECIALIST_EVIDENCE_CANDIDATES and CASE_ASSIGNMENT. Generations must belong to each true upstream provider and advance on EVERY relevant mutation, including A-B-A and revoke/regrant. The application does not mint fake generations, infer them from pointer hashes or grant professional authority.

Each provider returns a frozen SyntheticAuthorityWitness(kind, subject, case_ref, case_version, generation). All three kinds, their order, exact signed specialist identity and exact case/version must agree. Missing callback, malformed data, wrong case or two observations of a different generation -> sanitized 503, with no success audit. Current signed expert role and independent live exact-case access must still pass, along with the existing SQLite audit/case/owner-input/questions verification, proposal-source checks and specialist governance candidate checks. No new write endpoint, no source licence, actual credential, consent, crop knowledge, AI inference or specialist decision.

A version-separated SHA-256 synthetic_versioned_context_fingerprint_sha256 binds the prior structural context fingerprint to all THREE separately supplied generations. This digest changes even if pointer content returns to the same earlier value after A-B-A. Optional expected_context_fingerprint must be this *versioned* SHA for the new endpoint. A stale expected digest -> 409 with no successful audit; invalid shape -> 422. Actual generation values and private evidence refs are never exposed. It remains a non-authorizing optimistic concurrency marker, not a signature or business decision.

CRITICAL LIMIT: Upstream providers must really own durable, monotonic case-scoped counters and return revisions tied to their actual value snapshots. Untrusted, reset, reused or falsely asserted generations do not establish ABA safety. Two reads cannot prove distributed atomicity, prevent changes after the last check, or replace a future cross-provider transaction/versioning protocol. In-memory callbacks here are test-fixtures ONLY; no Production guarantee is claimed. Earlier routes cannot detect all ABA changes and remain unchanged.
