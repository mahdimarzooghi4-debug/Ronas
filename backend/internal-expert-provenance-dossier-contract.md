# Ronas — atomic redacted expert provenance dossier (LOCAL/TEST)

**Scope:** Strictly opt-in `GET /api/v1/agronomy/assigned-drafts/{ref}/provenance-dossier` available only with the existing synthetic expert question ledger and exact case assignment. Business candidate D1-DATA-01/02, D1-SCI-01, D1-REV-01..04 remain **unapproved**. This dossier is not a qualified-specialist review, accepted programme, source licence, evidence access warrant, model execution record or operational cultivation plan.

## Transaction and authority

The specialist's Keycloak signature, role and *current case-specific assignment* gate access. One existing ledger transaction verifies all case, input, question, owner response, receipt-inspection and audit history. The current input revision/digest is read from the immutable household-owned input journal, **never supplied by the API caller**. A pinned synthetic AI fixture, if present, must pass `inspect_proposal_structure` against that exact input and case. Where a synthetic scientific basis fixture exists, the separate current source catalogue callback must pass `inspect_scientific_basis_structure` for the exact manifest and current version/rights/review-pointer values. The source callback is checked in that same read; an unavailable/drifted source, changed household input or stale proposal fails closed with generic 503, **not** a partial response. Case/role/assignment denial is 404, no authenticated bearer is 401.

The read incorporates the existing verified per-track question/response/inspection evidence index. For each of exactly three canonical independent tracks, it additionally matches the **latest question's persisted input revision and digest, source-basis manifest and proposal-content digest** against the currently bound synthetic fixture. `latest_question_fixture_binding_matches=true` means *only this four-part structural equality*, and only if an independent current source-catalogue snapshot matched; it is **not** proof of source existence, legal service/Training rights, scientific validity, real household consent, model execution or specialist approval. All consequence/approval flags stay `false`; each track remains `NOT_REVIEWED`, regardless of receipts.

One `READ_ALLOWED` audit event with access mode `AGRONOMY_SYNTHETIC_PROVENANCE_DOSSIER` is committed only after a complete successful projection. It is **not** a separate persistence ledger. The same existing mutation/audit append-only protections, concurrency and integrity checks remain in force.

## Redaction, drift and semantics

The response exposes only case ref/version, latest input revision, unverified scientific basis candidate revision/source **count**, unexecuted proposal stage **count**, and each review track's question revision/count, last synthetic response-received/receipt-seen markers and structural fixture-matching boolean. It does **not** disclose household answer/evidence refs, question reasons/evidence refs, internal model artifact/run identifiers, model/proposal/input/science digests, raw rights documents, source IDs, stage IDs/instructions, personal information or any agronomy recommendations.

Without a pinned proposal, the API can show the old immutable history but never claims a current fixture binding. Without a separate current source catalogue, science is `NO_CURRENT_CATALOGUE_CHECK`, not verified. Later input correction keeps old question evidence but refuses a stale proposal dossier until a current fixture exists. Scientific source/rights changes invalidate new dossier reads instead of reviving old science. No standalone expert authority or new POST/approve/reject endpoint is added.

Testing covers three lanes, matching and stale bindings, redaction, role+live assignment, default route isolation, integrity failure, source-rights drift and one audited read.
