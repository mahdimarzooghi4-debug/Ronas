**Status:** technical preparation only. Candidate Business D1-SCI-01/D1-DATA-01/02/D1-REV-01..04 is unapproved. This is **not** independent agronomy advice, a source-rights licence, a certified specialist profile, real AI inference, approved individual plan, or a readiness score.

## Why another view?

Before this slice, the exact-case signed specialist workspace had distinct, audited read-only handoff, evidence timeline, and specialist scope-drift diagnostics. Fetching those via separate HTTP requests could mix input revisions, synthetic sources and specialist candidate history; SHA-256 fingerprints cannot serve as approval tokens. This slice is a **single read**, not a parallel ledger and not a new independent business workflow.

`GET /api/v1/agronomy/assigned-drafts/{ref}/review-context-impact?observed_specialist_revision=N`

Requires explicit nonnegative case-local per-specialist evidence revision `N` (0 allowed for no prior candidate). 401 invalid/unsigned token; 404 wrong engine/role/not-currently-assigned; 409 unknown specialist evidence revision; 422 malformed query; generic 503 if shared database/audit has been tampered, current household input or proposed plan is stale, source/rights candidate pointer differs from the separately checked current catalogue, or independently supplied specialist registry is unavailable/malformed/stale.

The same SQLite `BEGIN IMMEDIATE` transaction verifies the entire shared audit/case/input/question/answer/sighting ledger, checks signature-verified role and exact **live assignment**, reads current owner-input revision, checks current synthetic proposal fixture against it, and (when basis candidates are configured) samples the independent current science catalogue **exactly once**, fail-closed on source/rights drift. It collects historical input/question/owner-reply/sighting rows once, validates them through existing `verified_synthetic_evidence_events` and `prepare_synthetic_review_handoff`, samples the independent current specialist evidence candidate registry **exactly once**, checks requested observed version via existing `project_assigned_specialist_scope_change_impact`, and strictly joins all three *redacted* projections. One authorized, completed read appends precisely **one** `READ_ALLOWED` audit event; failed reads never append one.

The redacted payload presents only: current household input revision and historical case-local evidence event count; current scientific source candidate pointer state (never actual scientific/legal verification); unexecuted internal-AI proposed-plan fixture presence/absence; current specialist candidate state, historical/current candidate revisions and unresolved/unknown conflict markers; and exactly three independent review tracks with historical question/owner-response/sighting counts, question fixture alignment and *declared* candidate track scope. It never exposes private input bytes, source and licence refs/digests, specialist subject, conflict-disclosure documents, question evidence/note, actual AI model/run/stage instructions, or global audit sequence.

The composite `synthetic_context_fingerprint_sha256` hashes version-separated CURRENT synthetic handoff identity + current/observed candidate identity + immutable evidence event count. It is **not signed**, not persisted, not an attestation or usable as a release/decision token. Historic AI proposal and science catalogue versions cannot be recreated. Old input/source mismatch still yields 503 instead of a misleading joined snapshot; use existing historical drift GET to inspect history when current context is stale. Specialist evidence *revisions* and explicit withholding can still be diagnosed in a 200 read without granting authority. `CONFLICT_NOT_ASSESSED` is not conflict clearance; `POTENTIAL_CONFLICT_DECLARED` remains unresolved. Nothing assigns legal expiry or professional competence.

All three tracks stay `NOT_REVIEWED`, `eligible_for_operational_reuse=false`; no consent, rights, real model execution, expert approval, plan acceptance, new cultivation advice, finance/marketplace activation, Stage or Production. No database tables, no new mutations or extra panels; default app does not mount this route. Both PR #1/#9 stay Draft/Open/Unmerged, Domestic #2 / Export #3 / Finance #4 OPEN.
