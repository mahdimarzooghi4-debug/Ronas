# Ronas — two secure browser-to-domain workflows (LOCAL/TEST)

**No new product policy, gate admission, consent, real household input, real geography, trade or production.** This larger product-flow slice connects two existing, independently controlled DEMO mutation domains to the existing two browser environments. It does NOT invent a third role environment or a new ledger.

## Domestic household browser scenario
Existing signed owner GET `/my-drafts/{ref}/input-revisions` shows the actual DEMO revision count, then offers **two clearly labelled fixed synthetic scenario choices**. Browser POST `/my-drafts/{ref}/input-revisions/demo-correction` stores only a deterministic opaque SHA-256 for the chosen local demonstration scenario and prior revision using the existing `append_owned_input_manifest` ledger command. No free text, agronomy data, location, photo, consent or personal information can be submitted. The latest rev and case version are supplied from the authorized page and checked as CAS inside the owner ledger; old forms fail 409. Success PRG-redirects to the authorized read page, not a hidden approval. Previously existing Bearer-only JSON correction APIs remain unchanged.

## Export operator browser scenario
Existing exact-case-granted Export admin GET `/admin/export/research/drafts/{ref}` shows the previously implemented unverified question and offers two fixed `DEMO-PRODUCT-*` and `DEMO-DEST-*` selections. Browser POST `/admin/export/research/drafts/{ref}/local-test-question` applies the same already-reviewed `record_export_research_question` command with expected case/question revision. No real product/destination/HS/market data or source rights are ever inferred. Success PRG-redirects to the case page. The pre-existing signed Bearer-only API path remains unchanged.

## Browser security boundary
Both opt-in POST routes require a currently Keycloak-verified server-side BFF session **and** strict same-origin Origin equality **and** exact per-session CSRF, with a bounded strict `application/x-www-form-urlencoded` schema; duplicate/unknown/malformed/oversized fields fail without executing domain commands. The original ledger enforces owner or active case-specific assignment within its transaction and appends the immutable domain/audit record in the SAME existing database. HTML escapes server-issued CSRF and DEMO-only refs. Content Security Policy is relaxed **only** for the two vetted form pages from `form-action 'none'` to `form-action 'self'`. Every other page remains `form-action 'none'`. Native forms need no client-side bearer token, and the browser access token is never exposed.

Validation: signed/cookie role and grant scope, CSRF/origin, CASE/REVISION stale optimistic conflicts, exact synthetic schema and absence of real input fields, PRG, independent Domestic-vs-Export isolation, reload/reopen audit integrity, and existing full Python/Node workflow CI.
