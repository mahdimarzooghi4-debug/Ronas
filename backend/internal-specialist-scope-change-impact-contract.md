# Ronas — per-case specialist evidence change impact (LOCAL/TEST)

**Status:** candidate Technical extension of the unapproved Business D1-SCI-01/D1-REV-01..04 and the existing synthetic specialist evidence registry. **Not** professional certification, review admission, legal appointment, conflict resolution, or real agricultural advice.

`GET /api/v1/agronomy/assigned-drafts/{ref}/specialist-scope-change-impact?observed_revision=N` is an explicit opt-in, read-only specialist diagnostic. Revision **N is a per-specialist/per-case evidence revision ordinal**, starting at 0 for no prior candidate; it is **not** a global audit sequence, timestamp, legal validity period or Business Gate state. A known old revision is compared to the most current immutable event for the same exact subject and case version. Future/negative/unknown revisions return sanitized 409 (query-shape errors return 422). This does not accept self-asserted 'valid_until' times, role-derived accreditation or an arbitrary caller-supplied rights/qualification decision.

Every read FIRST verifies the existing append-only case/security/audit ledger, signed Keycloak `agronomy_expert` role and CURRENT independent exact case assignment. Revocation => 404 before the candidate authority is consulted. The independently configured optional immutable `SyntheticSpecialistEvidenceRegistry` is sampled **once** inside that same DB transaction; absent configuration shows explicitly no candidate; malformed/unavailable source or stale case-version pointer fails closed with generic 503. One successful read appends a `READ_ALLOWED` audit entry under `AGRONOMY_SYNTHETIC_SPECIALIST_SCOPE_CHANGE_IMPACT`. There is **no new POST, grant mutation, approval transition, or modification of existing _allowed / specialist decision permissions**.

Comparison is scoped to exactly one subject + case + pinned version. Other cases' events cannot change the returned per-scope fingerprints or status. The digest is a domain-separated SHA-256 of structurally pinned unverified DEMO references and history, never a signature, persistent credential, source content attestation or lawful record. Payload hides the subject, underlying qualification/appointment/conflict references and hashes and actual conflict disclosure. It identifies changed qualification pointers, changed appointment pointers, changed conflict disclosure pointers, changes of declared candidate track scopes, observed vs current conflict declaration, number of subsequent re-recordings and withholdings and explicit case-local evidence revision drift.

**Invariants:** A candidate's declared tracks cannot become granted authority. `POTENTIAL_CONFLICT_DECLARED` remains **unresolved**, while `CONFLICT_NOT_ASSESSED` is not a verified 'no conflict'; after a withdrawal conflict becomes **unknown**, never cleared. The report does **not** infer legal expiration/TTL, old live-case grants, professional qualification, independent conflict clearance or appointment validity. When a candidate is withheld, earlier snapshots remain historical and **cannot** be reused for new decisions, even if a later version structurally matches older content. Current valid technical read permission is different from real scientific programme-decision power.
