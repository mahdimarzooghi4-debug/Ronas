# Ronas — connected specialist → household → specialist LOCAL/TEST loop

**Scope: independent DOMESTIC browser user journey only; 2026-10-11.** This is not a real crop plan, consent, source license, professional credential or accepted human decision. It reuses the SAME existing SQLite `SqliteSyntheticExpertQuestionLedger` and its existing signed Bearer APIs. No new domain schema, independent ledger, external adapter, role environment or business approval.

## Three independent actions with separate signed actors

1. **Assigned expert requests missing evidence.** In the existing shared-user agronomy page `GET /agronomy/assigned-drafts/{ref}/review-questions`, three explicit fixed DEMO buttons correspond to the three *existing* independent review tracks. A form is shown **only if** the current synthetic proposal is structurally bound to the current household input version and science source. Historical questions remain visible when an old proposal becomes stale, but new forms fail closed/are absent. The new session/Origin/CSRF-protected POST `/agronomy/assigned-drafts/{ref}/review-questions/demo-question` calls the current `record_assigned_synthetic_review_question` domain command; the ledger rechecks the signed role, current exact-case assignment, input/proposal/science and per-track revision under the authoritative transaction.
2. **Household responds only to the latest current input-adequacy question.** In `GET /my-drafts/{ref}/question-responses`, a fixed `DEMO-REPLY-ALPHA/BETA` reference selector is offered only if the latest question is unanswered and bound to the current owner input revision. Session/Origin/CSRF-protected POST `/my-drafts/{ref}/question-responses/demo-reply` calls the pre-existing `append_owned_question_response`, checking actual ownership and same input/question version in the ledger. It records a DEMO *reference*, not a free text answer, evidence document, real household information or consent. Historical answers remain visible to the owner; the specialist only sees a response-present marker.
3. **Expert independently observes the response receipt.** If the current input-adequacy question has a recorded answer and the specialist has not already inspected its receipt, their existing case page shows a button; the bounded POST `/agronomy/assigned-drafts/{ref}/review-questions/demo-inspection` calls the existing `inspect_assigned_synthetic_response_receipt` domain command with current source/assignment/input checks. This only records **presence of an answer**, not its content, science adequacy, formal review, professional clearance, approval, instruction, plan or finance activity.

Each form is opt-in, `application/x-www-form-urlencoded` with exact small input set, authenticated Keycloak browser session, exact HTTPS Origin and CSRF. 303 redirect-after-POST returns to same permission-checked case page; an old form gets sanitized 409, an unassigned/wrong principal 404, unexpected payload 422, invalid session 401, corrupt source 503. Only those pages set `form-action 'self'` CSP; no bearer tokens in UI. All standard Bearer JSON APIs remain unchanged. Existing role UI navigation links to case-specific interaction histories.

## Explicit decisions not inferred

A question is NOT an agronomy review or plan, a household reply is NOT data-adequacy verification or consent, receipt observation is NOT scientific judgment; approved flags remain false and previous versions are never rewritten. Real customer inputs and crop monitoring cannot be collected without scoped Business authorization, purpose-bound rights, real accredited reviewer/proposal, actual source license and model governance. Business Gate #2 and Finance #4 (and independent Export #3) remain OPEN. PR #1/#9 Draft/Open; no Stage/QA/Release/Production.

## Parallel Export E0 read-model extension in this work package

The independently authorized Export admin case GET now shows **the actual full append-only history** of that case's previously stored LOCAL/TEST draft product/destination reference questions, instead of only the latest revision. The existing current-grant, `BEGIN IMMEDIATE` whole-ledger verification, immutable row audit and same-transaction read audit apply. Every historical row contains only its ordered question revision and two `DEMO-*` references, explicitly marked `UNVERIFIED_LOCAL_TEST_DRAFT`; no action IDs, actor hashes, audit sequence, source rights, real products/countries or findings are disclosed. The Persian Export case page retains both current question editing and historical revision visualization within the same one-admin environment. Revocation or unrelated assignment prevents the entire history read; it does not leak a hidden case or count. This read surface is not Export Trade, Finance or research approval.
