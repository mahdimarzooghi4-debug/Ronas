# Ronas — source-owned candidate observation boundary (LOCAL/TEST)

**Scope:** A new **opt-in** `SourceOwnedCandidateAuthorityRead` can be bound to the existing signed GET `/api/v1/agronomy/assigned-drafts/{ref}/review-context-versioned`. Default runtime, the earlier independently sampled version callbacks, and the local dual-file checkpoint adapter remain unchanged. No new route, writer, provider account, review decision, business status or Production configuration is created.

## Ownership and trust contract

The three **independent owners** supply scientific source candidates, specialist evidence candidates and current candidate assignment. Each owner callback must read the **actual current typed source-owned candidate state and the generation committed with it in ONE owner-controlled persistence transaction**; `SourceOwnedCandidateObservation` carries `SyntheticAuthorityWitness`, the typed current snapshot, and a SHA-256 digest recomputed from that snapshot. The caller passes the exact signed actor, DOMESTIC case ref and current case version. Missing callbacks, missing generation, malformed typed state, wrong actor/case/domain, invalid digest, stale data, callback errors, and independently changed values fail closed as sanitized HTTP 503, without successful read audit. This adapter DOES NOT make arbitrary callback assertions independently trustworthy: future real owner adapters need their own storage-level tests and trusted deployment integration. No Production owner adapters exist.

The workspace refuses to combine source-owned observations with loose counter-only callbacks or the local checkpoint adapter. The guarded GET consumes **the returned typed owner snapshots** when projecting the source/specialist context, not separately sampled snapshots. Source generation and digest are re-observed before the successful audit and compared with the first observation; in-flight content drift or ABA fails closed. Candidate assignment must explicitly be TRUE at both observations **in addition** to signed Keycloak `agronomy_expert` role and the separately rechecked current case-specific live grant. Absence/revocation yields 404 before a successful read. The context precondition includes owner generation **and snapshot digest**, so a later request with an earlier fingerprint is rejected 409 even if redacted structural fields are unchanged. No source hash, raw snapshot, counter or private credential is emitted.

The existing household input revision remains owned by its separately verified case ledger and still pins the synthetic proposal. Where a scientific basis is configured, matching source candidates must still pass the existing exact scientific manifest check; specialist scope history is also verified. A source pointer, evidence document or candidate assignment is **never** proof of rights, licensed specialist qualification, consent, scientific suitability, conflict clearance or an approved cultivation plan. All independent human decisions remain outstanding.

## Explicit limitations

There is **no distributed transaction or global snapshot** across the three source owners, the case ledger, Keycloak or the audit ledger. Reads before/after cannot rule out a change immediately after the final check, and an untruthful, non-monotonic or restored independent provider can lie about its version. This contract is stronger than independently sampled counter-only witnesses but **is not a Production-ready source integration or externally attested authority**. Source providers, credentials, backfill/recovery policy, true business decisions, and off-host evidence remain unselected and unapproved. Business gates #2/#3/#4 remain OPEN; PRs remain Draft/Open/unmerged, with no Stage/QA Gate/Release/Production.
